# The Wiz

Storefront for **The Wiz** — a series of premium study notebooks for medicine,
pharmacy and dental surgery. One notebook per subject, year by year.

The landing page speaks for the whole series and sells whichever edition is
shipping; the catalogue carries the rest.

Monochrome editorial design: white paper, black ink, hairline rules, large
whitespace. Built with Next.js App Router, Tailwind CSS v4 and Framer Motion.

```bash
npm install
npm run dev      # http://localhost:3000
npm run build
npm run typecheck
```

---

## Where to edit things

Almost everything you will want to change lives in one file.

| What                                                | File                         |
| --------------------------------------------------- | ---------------------------- |
| **Books: specialties, years, subjects, prices**      | `lib/catalogue.ts`           |
| Landing-page copy, FAQ, testimonials, social URLs    | `lib/content.ts`             |
| Colours, type scale, radii, shadows, grain           | `app/globals.css` (`@theme`) |
| SEO metadata + Product JSON-LD                       | `app/layout.tsx`             |
| FAQ JSON-LD + section order                          | `app/page.tsx`               |
| Social share image                                   | `app/opengraph-image.tsx`    |
| Order / waitlist endpoint                            | `app/api/order/route.ts`     |

Set the live domain in `site.url` (`lib/content.ts`) before deploying —
`sitemap.xml`, `robots.txt`, canonical URLs and Open Graph tags all read it.

## The catalogue

### Languages and GitHub Pages

English is served at `/`; French is served at `/fr`. The EN/FR switch preserves
the current course, year or book. French catalogue translations live in
`lib/french.ts`; French pages are generated by `app/fr/[[...path]]/page.tsx`.
The original PDF content is unchanged in either language.

`npm run build:pages` produces the GitHub Pages site in `.next-pages` with the
`/the-wiz` base path. Push to `main` to publish through GitHub Actions.
Full PDFs in `Content/` are excluded from Git. The committed 10-page previews
and generated manifest allow builds without the original content folder.
After regenerating previews locally, optionally install `pymupdf>=1.26` and run
`python scripts/optimize-previews.py` to reduce scanned images to 150 DPI for
faster downloads. The first 10 pages and their dimensions are preserved.

GitHub Pages serves static files, so online orders and waitlist submissions
are disabled on that deployment. The normal Next.js build retains its API;
the French version currently provides browsing and previews only.

### MedWIZ course previews

Visit `/courses` for the real MedWIZ library, organized by the years found in
`Content/MedWIZ`. Each year and course has its own page, with accent-insensitive
subject search and a PDF preview. The existing `/books` store catalogue remains separate.

`npm run previews` discovers the source PDFs recursively, copies only the first
10 pages into fresh PDFs in `public/course-previews`, and regenerates
`lib/courses.generated.json`. It also runs automatically before development and
production builds. Add courses using the filename `MW-NN-Subject.pdf` and restart
the dev server or rebuild. Courses shorter than 10 pages expose only their available pages.

Full source PDFs remain outside `public` and are never served by the app. Only
the truncated preview files are public (including when downloaded). Do not copy
the original `Content` directory into a public hosting directory.

A book is identified by **specialty → year → subject**, and books are *derived*
from the curricula in `lib/catalogue.ts` rather than listed one by one. Add a
subject to a year's array and you get a page, a catalogue entry, a sitemap
row and a waitlist form for free.

> ⚠ **The subject lists are placeholder curricula.** They are a plausible
> guess, not your real programme. Replace them — everything downstream
> regenerates.

```
lib/catalogue.ts
  specialties[]   Medicine (7 years, 6 taught), Pharmacy (5), Dental surgery (5)
  curricula{}     subjects per taught year, indexed from year one
  overrides{}     per-book facts: status, price, pages, title
```

Every year also gets an automatic **year bundle** alongside its subject books.

### Routes

| URL                                     | Page                             |
| --------------------------------------- | -------------------------------- |
| `/`                                     | Brand landing page, sells the flagship |
| `/books`                                | Full catalogue, filter by specialty and year |
| `/books/[specialty]`                    | One specialty, all years         |
| `/books/[specialty]/year-N`             | One year, all subjects           |
| `/books/[specialty]/year-N/[subject]`   | The book page — cover, contents, order panel |

All of them are statically generated at build time (120 pages today).

### Making a book buyable

Add an entry to `overrides` in `lib/catalogue.ts`:

```ts
"medicine/3/semiology": {
  status: "available",
  price: 3200,
  pages: 240,
},
```

Anything still `coming-soon` shows no price and swaps the order button for a
waitlist form. Attempting to order an unavailable book is rejected server-side,
not just hidden in the UI.

### The flagship

The one book that exists today predates the per-subject model — it covers a
whole year — so it is modelled as `kind: "bundle"` rather than reshaped into a
subject it is not. Its title is overridden to "The Wiz — First Year Medicine"
to match the printed cover.

## Replacing the placeholder images

The three notebook previews and the founder portrait are SVG placeholders.
Drop real files at the same paths and nothing else needs to change:

```
public/spreads/spread-01.svg   Chapter summary preview
public/spreads/spread-02.svg   Anatomy diagram preview
public/spreads/spread-03.svg   Blank note pages preview
public/portrait.svg            Founder portrait
```

The spreads are laid out at a 4:5 ratio (`1000 × 1250`) and the portrait at
`800 × 1000`. Any aspect ratio works — the layout adapts — but keeping these
proportions preserves the intended rhythm. If you switch to JPG/PNG, update the
paths in `lib/content.ts` and you can then remove `dangerouslyAllowSVG` from
`next.config.ts`.

The **notebook cover is not an image**. It is rendered as real DOM in
`components/notebook/notebook-3d.tsx` so it stays sharp at any size — edit the
typography there.

## The 3D notebook

`components/notebook/notebook-3d.tsx` builds a real cuboid from six CSS 3D
faces (front cover, back cover, spine, fore-edge, head, tail). It floats on an
idle loop and rotates from scroll progress passed in as a Framer Motion value.

Geometry comes from three custom properties, so it scales with the viewport
without any JS measurement:

```css
--bw   cover width    clamp(190px, 24vw, 320px)
--bh   cover height   calc(var(--bw) * 1.4)
--bd   block depth    calc(var(--bw) * 0.11)
```

Cover typography is sized in `em`, so changing `--bw` rescales the whole object.

`NotebookCover` is exported separately and reused flat in the order panel.

## The order form (MVP)

`Order now` opens a modal (`components/order/order-dialog.tsx`) that posts to
`POST /api/order`. The same endpoint handles two intents:

- `order` — full details, returns a reference like `WZ-K2E6TD`
- `waitlist` — name and email only, returns `WL-2RYU4K`

The route validates the book, the intent and every field against the catalogue.
**It currently only logs to the server console.**

To go live, replace the `console.info` in `app/api/order/route.ts` with your
fulfilment step — an email (Resend, SendGrid), a database row, or a webhook
into a spreadsheet. The response shape stays the same, so the UI needs no
change.

No payment is taken in the form; payment method is captured as a preference and
confirmed by email. Wiring a real processor is a separate step.

## Motion

- **Smooth scrolling** — Lenis, in `components/providers/smooth-scroll.tsx`.
  It also eases in-page anchor jumps and exposes `useScrollLock()` for the
  modal.
- **Entrances** — `Reveal`, `RevealGroup` and `RevealItem` in
  `components/ui/reveal.tsx`. One gesture across the whole page: fade + 24px
  rise, `cubic-bezier(0.22, 1, 0.36, 1)`.
- **Parallax** — hero copy, the notebook, and each spread in section 3 drift at
  slightly different rates.

Every animated surface checks `prefers-reduced-motion`. With it enabled, Lenis
never initialises, the notebook holds a fixed angle, and reveals become plain
fades.

Skip link, visible focus rings, `aria-expanded` on the FAQ accordion, a focus
trap and `Escape` handling in the order dialog, labelled form fields, and
`aria-live` on the quantity stepper.
